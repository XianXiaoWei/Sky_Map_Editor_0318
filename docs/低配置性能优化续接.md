# 低配置性能优化续接

2026-11-21。用户反馈所有地图延迟五六秒、FPS 为 0–1，本批优先处理渲染开销；Windows 设备帧率不由 Linux 软件渲染结果推定。

## 实现

默认自动档在 CPU 软件 Vulkan 上选择基础画面：保留原几何、索引、绘制组和透明/深度状态，使用无材质贴图的简化颜色与法线光照。基础画面为明确编辑器画质，不是原游戏材质。可手动选择原材质减少特效或完整画面。硬件自动档先用原材质减少特效，持续高耗时后切基础画面。长边从 480（软件）或 960（硬件）开始，按实测成本在 128–960 内调整；完整画面软件上限 640、硬件上限 1920。

性能路径保留天空、雾、透明重建和 Tonemap，在 GPU 内连接附件；每帧合成只有一次 GPU 提交和同步等待。关闭实体云、时间抗锯齿与逐帧亮度测量。最终只通过管道传回 RGBA8；浮点中间图像留在 GPU。管道拆包直接填充最终缓冲区，去除不断增长的 Buffer.concat。

透明排序只发送完整绘制索引排列，复用几何、贴图与管线；本地包围盒缓存，世界变换及相机距离仍实时计算。基础画面按同一相机视锥剔除全在视野之外的绘制批次，保留碰到边界的批次和非仿射矩阵；原材质有顶点形变，保持其既有绘制范围。剔除不删除场景对象或交互状态。场景标签不再拦截鼠标。静止画面按需绘制，FPS 归零不代表卡顿；相机移动时才测绘制性能。画质分支不关闭现有物品事件、Float 状态和环境更新代码，完整物品生命周期仍逐项恢复。

Windows 包继续使用 Electron 官方运行库。把官方 Vulkan loader 同时放在原生 helper 目录，防止快捷方式工作目录变化造成 DLL 查找失败；硬件 Vulkan 初始化失败且用户未指定 ICD 时，自动尝试包内官方 SwiftShader。此 Windows 回退尚无 Windows 实机执行证据。

## 行为清单

[完整列表](Objects.level.bin逻辑实现列表.md)覆盖 283 个声明类、280 个含顶层对象的类、49,824 个对象；另有同名 JSON，逐类列现有证据、职责、保存引用、缺口和六项验收。

用户标准为游戏可观察行为、状态、依赖输出和事件顺序相符，不要求内存布局或代码 1:1。当前 49 类部分实现、4 类实现中、227 类待实现、3 类仅声明待核实，完整行为验收仍为 0。Emitter、MoteParams、Mote、SpawnMotes 的新增发射代码尚未完成独立核验和实际粒子消费，不计完整类。

蜡烛链含 CandleObject（1077）、Flame（290）、OnFlame（154）、SetFlame（43）、CandleGate（23），Water 为 38 个实例。它们与账户/收集物、机关和其他所有类型均在列表；此批性能优化不冒充这些类已经完整实现。

## 验证

最新项目测试、类型检查、构建、原生 GPU 检查、逐图实测、包验证及 reference 哈希见 performance-continuation-verification.json。阶段实测已发现仅降低分辨率的路径仍在 Dawn 卡顿，因此最终自动档补基础画面，不能拿此前原材质路径结果当最终优化验收。

完整帧率样本、计时器延迟、是否真正移动相机、场景/材质上传次数及分辨率见 performance-auto.json。软件渲染允许较低内部尺寸和画质；不能保证任意 CPU/显卡达到固定帧率。真实水面、蜡烛和粒子生命周期、原场景完整度与 Windows 实机验收仍按清单推进。
