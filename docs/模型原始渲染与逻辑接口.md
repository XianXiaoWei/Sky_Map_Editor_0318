## 原顶点与 UV

Model 构造 `0x100467d07..0x100467e0b` 保留原独立流：position/color 为 float3 + UNORM4，normal 为 SNORM4，UV 为两个 half4；兼容烘焙的三组照明为三个 UNORM4。编辑器上传时只交错成 48-byte 顶点，原位置/色彩、法线、UV 和照明字节保留。每个模型另传自己的矩阵，不把全部模型合并成同一世界矩阵。保存的剪切和非均匀缩放也保留；只有用户明确编辑变换时才重新组合矩阵。

| Mesh shader 输入 | 网格 UV 集 | Mesh/MeshSh 常规片元用途 |
| --- | --- | --- |
| `a_uv0.xy` / `v_uv01.xy` | UV0 | `u_normTex × u_normTexScale`、`u_diffuse1Tex × u_diffuse1TexScale` |
| `a_uv0.zw` / `v_uv01.zw` | UV1 | `u_lightTex` |
| `a_uv1.xy` / `v_uv23.xy` | UV2 | 常规变体未采样；其他变体的 attribute texture 可使用 |
| `a_uv1.zw` / `v_uv23.zw` | UV3 | `u_diffuse2Tex`；有些变体将其命名 `v_uv4` |

[原平台 GPU 核验](model-uv-gpu-check.json) 使用实际 DayHubCave #339 / PlatformRain_01 / MeshSh 与原烘焙/贴图，仅在临时上传副本中平移一组 UV。7,657 个覆盖像素，UV0 改变 22,768 个 RGB 分量、UV3 改变 22,771 个；UV2 的输出字节完全相同。UV1 在这个模型采样原 White 常量贴图，因此输出同样不变；不能借此宣称 UV1 不参与渲染。原 shader、资源与地图字节均未改写。

地形的 RockFace/Terrain 是另外一套：世界位置 × `u_matUvScale` 生成三向投影，按法线权重混合顶面/侧面纹理。不能将其材质 IDs/权重误认成模型的四组 UV。MeshMotion 的 `a_uv2` 可以承载上一帧位置，也不能只按名称认成 UV。

## 材质、默认值和显示状态

自定义 LevelMesh 使用保存 shaderName/参数；默认分支使用已核验的 MaterialDef shader + `Mesh` 和默认参数生成。上传区分 LevelMesh 的 texture valueType 2 与 MaterialDef 投影的 texture kind 1，不误用两套枚举。[默认材质 GPU 核验](model-default-gpu-check.json) 使用 CandleSpace #342 Cube、RockFaceShMesh 和 WallSh，8,072 像素覆盖且全部输出有限。

`Model +0x227` 是本帧 visible，`+0x228` 是 enabled，`+0x32d` 是 render。原构造 visible/enabled 为 1，LevelMesh Create 随后转发保存的 enabled；false 会清 visible 和 `+0x3c0`。SetEnabled(true) 本身不会将 visible 改回 1。保存 `visibleInWorld` 为另一字段，未用作启用开关。当前地图初始显示尊重保存 render/enabled；完整 Visibility/Model 更新尚未接入。

缺失贴图、烘焙不兼容、native skinning、未接入的 RenderList 和全局 uniform 按对象显式记录。诊断模型仍可检查几何，不能计成原材质绘制。尤其 1,007 个 DarkStone 的空贴图参数、动画模型、Blended/BlendedWithBackfaces、Ghostly、Skybox、FogVolume、scene probe SH/光源等仍待恢复。

## 后续类共用接口

`OriginalLevelMeshModelEndpoint` 按原 LevelMesh 地址读取实时 `+0x228` Model 指针，提供 `getEnabled/setEnabled/getTransform/setTransform/submit`。Enable、Parent、Timeline、TransformObject 和后续绘制调度可以使用同一个 endpoint。没有另分配一个冒充原构造完成的 Model。原队列和资源生命周期由场景所有者接管；没有 Model 指针时提交抛明确依赖边界。

当前地图预览继续使用已有 object ID 和恢复的对象播放内核：模型变换更新使其材质绘制重新绑定；显示变化使同一对象进入或退出绘制；编辑器修改材质会从更新后的同一 ObjectNode 重新绑定。`Model` 指针真实创建和 native endpoint 与完整场景调度连接仍待闭合。纯模型变换复用原材质管线和贴图，仅更新矩阵 uniform；原平台 GPU 检查记录 1 次材质上传 / 1 次 uniform 更新，44,394 个 RGB 分量随变换改变。材质动画的 `u_time` 进入共同 float32 时钟；PlayAnimation/SetMeshShaderParam 的完整原运行不能由此视为完成。

## 软件驱动边界

先前原 RockFace shader 的 12 个非有限 RGB 分量已定位到 llvmpipe 的退化 UV 各向异性采样。只对 llvmpipe 改用三线性；硬件继续按设备能力使用请求的各向异性。原 shader/texels 不改、不替换 NaN。[3 个原三角面的复现](material-degenerate-uv-check.json)：旧程序请求 2/4/8/16 时仍各产生 12 个非有限分量，新程序全部请求无非有限数。此项属于编辑器驱动兼容，不算原游戏逻辑恢复。历史失败记录继续保留；DayHubCave 额外 cloud 验证单存于 material-DayHubCave-cloud-check.json，较早三地图 cloud 记录保留。
