## 进入主视口的管线

材质预览现在运行：原地形/裙边及 CloudCore → RGB/signed-depth → DepthDownsample / Gather / Quarter → CloudFluffySuperCoarse 1/8 R16F → CloudFluffyCoarse 1/4 R16F → CloudFluffy 半尺寸双 RGBA16F → 同 pass CloudCard → FogUpsample → 原 FXAA → Tonemap。

CloudCore 读取上一帧 CloudA；切地图、视口尺寸变化时显式初始化历史。云卡使用原 28-byte 动态顶点、half UV、SNORM 法线、alphaMult、原世界球视锥筛选及排序。本轮不自动生成尚未恢复运行来源的云粒子。

实体云噪声使用游戏的 Tex3D/CloudFluffy.vol 和原归一化/首尾轴交换，保留稀疏、距离及三张环境光图集；没有替换为自制 Perlin。CloudEnvParams 起伏默认值 0 来自原构造函数，地图的 autoStart/空间环境字段覆盖初始值。云 RGB 从原 material 80 读取，alpha 取地图 sunOcclusionScale；噪声深度 2.5、透光深度 0.5、sparkle 0.15 和风倍率 0.4 均有原程序证据。

屏幕蓝噪声绑定 NoiseBlue3Ch（原 nearest 和 gamma 配置），扰动绑定 HeatTex/Heat.png。Vulkan 读回从顶部开始，原 fullscreen UV 从底部开始，按着色器的具体采样方式处理附件：CloudCore 历史、SuperCoarse 深度、Fine/Card 深度保持顶部顺序；Coarse 的顶点 UV 深度、粗 T 纹理和 Fog 输入翻转为底部顺序。原云/深度 AIR 转译与原 FogUpsample/Tonemap GLES 片元实际执行。

## 材质渐变修正

原导出器以首见顺序全局合并相同材质。若早期地形块先出现 Grass、后期块需要 Sand→Grass，后期块会被画成 Grass→Sand。

现在按原 MaterialDef ordinal 在 opaque/decal/skirt 各阶段合并和排序，保留每个三角形的材质层次，也避免把纹理重复上传数百次。原 Rock/Sand/Grass shader 和贴图的两个合成地形块前后对照中，后期块 6,974 像素改变，早期块保持一致。此项不证明已恢复全游戏 shader handle 调度，也不覆盖所有材质采样差异。原独立理想采样误差报告继续保留。

## 当前适配和限制

- 主视口 sampled wind 为显式零，CloudBarn 原偏移仍随时间推进；全局/局部风场、轨道风未闭合。
- 云卡没有恢复默认/完整烘焙 lighting 的生成，采用明确的中性预览值；真实 Visibility 遮挡未接入。
- 场景 probe 当前为天空预览，模型原材质、点光/阴影、体积雾场、完整透明列表、水、泛光和运动模糊仍有缺口。
- 原 luminance feedback 尚未接入；先用 FogUpsample 重建 HDR 计量几何平均亮度，再用明确的编辑器曝光适配运行原片元和 sRGB 显示转换。不是原自动曝光一致性证明。
- opaque 当前共享 RGBA32F，进入原半浮点深度链前转换一次 half RTE；原 Metal 每 draw 的 half 舍入和实际原游戏画面仍未验收。
- 软件 Vulkan 为长边 640 像素预览，硬件 Vulkan 上限 1920，保持原管线 1/8、1/4、1/2 比例。软件驱动帧率较低；可暂停材质动画后移动相机检查。

## 2026-11-15 实体云续接校验

修正了两个会影响云轮廓与遮挡的输入错误：低分辨率通道错误地绑定全尺寸 `u_viewportSize`，以及对 AIR 屏幕坐标深度纹理统一翻转。SuperCoarse、Fine、CloudCard 使用原 AIR `gl_FragCoord.xy / u_viewportSize`；Coarse 使用顶点传入的 UV，必须独立选择纹理方向。云顶点的射线锥半径也使用当前通道宽度。

原 AIR 的坐标运算有直接证据；当前通道尺寸和 Vulkan 存储方向通过真实 GPU 空间对照确认，尚未执行原 compositor 的逐通道 viewport 参数上传调用。新增 `cloud-spatial-depth-check.json`：128×96 和 127×95 两种尺寸、四个遮挡象限、全部四个云阶段，238,464 个分量与对应位置的独立全近/全远深度 GPU 帧一致。七个故意错误的行方向/尺寸绑定均产生差异，证明用例能捕获此次问题。此检查不替代原 Metal 验收。

原 CloudBarn::Update 在 `0x100212716` 设置 r8=1 调用相机查询。当前相机改为直接执行已恢复的 r8=1 算法：起伏后的查询位置减去风 scroll，再采样原 CPU 噪声；避免从 Avatar 结果加减差量引入额外舍入。原 `0x100212727..0x10021277c` 明确生成 `[max(noiseDepth,.001), queryDistance + max(noiseDepth,.001), translucentDepth, sparkle]`。旧视口把前两项颠倒，并反转查询距离符号；现已按原指令修正。云外标准参数是 `[2.5,.5,.5,.15]`。

`cloud-camera-query-oracle.json` 的 288 组样本直接运行原相机查询、原 CPU 噪声函数与原 Update 参数写入指令。真实 CloudFluffy.vol 上传字节、随机风 scroll、云内外边界、零/极小 noiseDepth、起伏和时间均参与；距离/法线、采样坐标/次数与全部四项参数的 float32 字节精确一致。距离场用明确的回调，libm 正弦值从原执行捕获；完整原游戏启动和 GPU 画面不在此检查范围。

诊断现在一次发布已完成帧，持续动画时不会读到下一帧的半截通道清单。暂停动画后移动相机，会补绘一帧更新 CloudCore 历史，shader 时间保持暂停。

Dawn、Prairie_ButterflyFields、Sunset 的相同相机已重新出图；`cloud-preview-compare.json` 与 `shader-effects/*-cloud-before-after.png` 保留左旧右新的对照。改善的是当前预览，仍可见部分黑色几何遮挡和低分辨率细节；原自动曝光、完整模型/天空照明、云卡照明及风场缺口继续保留，不用额外模糊掩盖。

复验：`npx tsx tools/cloud-camera-query-oracle.ts`、`npx tsx tools/cloud-spatial-depth-check.ts`、`npx tsx tools/viewport-cloud-check.ts`、`npx tsx tools/cloud-preview-compare.ts`。机器码对照使用原文件的只读映射副本，不修改 reference。

## 继续处理材质与噪点

地形贴图原先只上传最高分辨率，远处或斜面会直接抽取高频法线/遮罩，缺少 mip 和声明的各向异性过滤。现按原 ImageDefs 的 source、gammaCorrection、disableMips、enableAniso 上传完整 mip 链；非 gamma 法线/数据保持 packed 通道，sRGB 色彩在 linear light 中取平均，alpha 保持线性，奇数尺寸覆盖全部原像素。支持 samplerAnisotropy 的设备启用请求，最高 16x 并受设备上限限制；不支持时保留三线性。PNG mip 生成采用明确的面积过滤预览方法，原 exporter 的法线 mip/压缩和原强度仍未建立逐字节一致性。

原 compositor 的 FXAA 分支位于 Fog 合成之后、Tonemap 之前（`0x100240676` / `0x1002415db`）。现接入原 Fxaa0.frag，沿用已验证的 fullscreen UV adapter，处理整个合成画面的细碎锯齿；不是自制整屏模糊。原 TemporalAa/MotionGen 分支仍未接入，不声称已完成时间抗锯齿。

窗口检查捕获到 CloudB 的运动向量在旧相机投影平面附近溢出 half，而读回打包拒绝 infinity，导致视口停止。现只允许 CloudB.yz 运动通道保留 IEEE ±infinity；CloudB 的 log-depth/weight、CloudA、最终显示仍严格验证。FogUpsample 仅使用 CloudB.xw，因此保留运动溢出不会污染当前显示；计数另行记录在 completed-frame statistics.nonfinite。没有把原 half/Metal 失败报告改成通过。

`viewport-filter-check.json` 的独立 Vulkan 检查：最高分辨率贴图的显式横向高频方差约 0.00323，mip 过滤后约 5.7e-31；原 FXAA 在指定噪声测试图上 Laplacian energy 从 0.06926 降至 0.02454，纯色区域零变化。这些指标只验证预览过滤能工作，不是原游戏视觉差异百分比。33 张地图的材质加载/两相机绘制重新通过，三张真实云地图重出图。`cloud-noise-compare.json` 和 `shader-effects/*-cloud-noise-before-after.png` 为左旧右新的实际画面。

## 2026-11-16 云噪声和实际数据段续接

原 Compositor `0x10024716e..0x1002471c7` 每帧读取三个 rand 结果，先转换为 float32，再乘 `2^-31`，写入 u_randomOffset。之前预览固定为零；现在在动画推进时更新，暂停和暂停后相机导航保留样本。预览使用明确的确定性 31-bit 随机流，不声称与原 Darwin 进程全局 rand 状态一致。

原 CameraSystem `0x1001e157e..0x1001e1a3d` 的 Gaussian 重建在明确的居中场景 jitter 下，四个 tap 为 `[-c,-1], [1,-c], [c,1], [-1,c]`（分别除以视口宽高），`c=0.09195452928543091`。128 组原机器码样本、1,408 个 float32 分量的随机转换与角点字节全部一致，见 `compositor-noise-oracle.json`。此检查不包含原八相位场景投影 jitter、macOS libm 和完整相机更新。

主视口恢复原 MotionGen、MotionDilate、TemporalAa GLSL。MotionGen 使用当前不透明深度和 CloudB，nearest 采样保留运动通道 infinity，原 +/- .5 clamp 后继续重投影。原 descriptor 为半尺寸 MotionGen/MotionDilate，TemporalAa 使用全尺寸当前合成色与历史色；Fullscreen 使用已有明确的 Reprojection quad 适配。新的地图和尺寸清空历史；编辑器导航视作 cameraCut；暂停 shader 时间和随机样本。移动模型 Motion 列表、真实原投影 jitter 和 Metal half 舍入仍未恢复。

`temporal-aa-check.json` 的受控图像检查中，RGB 首帧/切镜头误差小于 0.00049（half 存储），纯色区域零差异，明确静止运动匹配、溢出运动 clamp 和历史 reset 通过。帧间平均 RGB 差由 0.15046 降至 0.06988；这个约 54% 的降低只针对指定噪声用例，不是游戏视觉误差下降百分比。三张地图左旧右新对照见 `cloud-temporal-compare.json`。

全量云检查发现 CandleSpace 有 Cloud.bin 而无地形/裙边，旧入口错误地要求有地形材质批次才调用云链。现由场景的实体云/材质模式显式请求管线，云单独存在时仍运行；诊断显示模式仍按当前模式显示。独立检查以云代理边界设置该图相机。`viewport-cloud-all-maps-check.json` 的 27 张含云地图、128×72、每图两帧全部执行通过；Dawn、Prairie_ButterflyFields、Sunset 的 320×180 两帧重新出图。这个低分辨率执行检查不证明全原游戏画面一致。

项目 121 项测试与类型检查通过。原 Metal/AIR 混合舍入和理想纹理采样失败继续保留。五段逻辑区划逐地图覆盖完整 LOD0；数据关联匹配 10,592/10,653 条资源名+GUID 模型烘焙，61 条未匹配保留。下一阶段按用户指令，先云与地形，再基础对象类，随后模型类/调用依赖与烘焙、裙边、遮挡联合恢复。
