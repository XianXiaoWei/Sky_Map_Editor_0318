## 原顺序与已修正的细节

FloatSplit 不是复制输入：输出 i 使用 `[i/N,(i+1)/N]` 分段后映射到 0–1；输入值和初始 N 捕获一次，成员查询之前仍重新读 count。非空输出不调用 Start。FloatEnable 则每轮重新读取输入，在 cast 前保存，再重新读下一轮 count；两类不能共用错误的固定列表循环。

FloatAdd 使用有序比较，不用会吞掉 NaN 的通用 clamp，且先限制上限、再限制下限；当上下限反向时顺序会改变结果。没有 output 时写回 target，amountFloat 可以和输入/输出相同。

IfEnabled 逐一查询全部对象，匹配后仍调用 GetEnabled；条件为 OR。匹配并 checkOnce 时原函数调用 Start 两次。原 GetEnabled 的元数据缺失分支会返回 true，但本轮调用驱动以明确服务模拟，未声称该反射链已恢复。

SetFloat 的 GameTime 内存输入先读 float32，再按 `speed * scale`、`* delta` 的顺序执行。统一验证识别了 18 个 math 参数字节差异；已修正 JavaScript 外部 double 输入未先舍入的问题，原失败证据保留在 [首次舍入差异](object-batch-rounding-initial.json)。logf/expf 用独立原调用捕获的 Linux 返回值验证指令顺序；不据此宣称原 macOS libm 一致。

Event 构造仅改写原函数写入的字节：sequence、autoStart 等未写字节保留分配快照，不能擅自清零。三个转发入口先清 active word，再按入口改变 +0x23，然后调用虚方法。Start 只在首次启动分配 Barn 序号，u32 回绕和重复启动保持原样；null Barn 写序号 0 并走明确日志服务。

PlaySound2D 首次提交全零的 128-byte options 和 432-byte parameters，填入 volume、mix 和 `0x40011`。原句柄 ID 会在多个调用点重新检查；更新 `ut` 时间参数前后也按原顺序检查。恢复启用只停止仍匹配的句柄，再启动事件，保留 launched 和句柄字段。真实银行音频不会用预览音频实现替代。

## /Data/Audio 与对象依赖

[音频运行依赖清单](audio-runtime-inventory.json)覆盖 8 个原 IMA ADPCM WAV、13 个 FMOD bank、12 个 FSB5 容器和 3534 个 bank 样本。全部 1,421,920 个有效 PCM 样本与 libsndfile 1.2.2 逐字节一致；fact 声明的有效长度排除末块填充。

33 张地图有 11 个音频功能类、752 个实际对象、210 个非空 sound/soundName 名称。清单按单独类保留配置字符串和对象引用。FSB5 sampleNames 是样本名，不是 FMOD event 路由；3534 样本的 bank 解码、事件/声音依赖、空间 listener、混音/参数与卸载仍待恢复。PlaySound2D oracle 使用全部 109 个真实对象的原 sound 名称，volume/mix/GameTime/句柄仍明确指定测试快照。
