# 0.2.0 材质与着色器进展

本轮完成原版 shader 变体选择、材质数据关联和检查界面。视口继续使用编辑器预览，原版 shader 的 GPU 上传和完整管线尚未完成。

## 原程序确认的选择规则

可执行文件 SHA-256：`3fa493e2542638299fd54d64e1b62aeb5b81c8f290176d955c3e38a27fa72b20`。

- Shader 注册函数：`0x1007d1ff0`；vs/fs/defines/group 在原生对象的偏移分别为 112/136/208/232。
- 资源加载函数：`0x1007d1340`，把源名称与 defines 原字符串传入 `0x1007d1150`。
- 哈希循环：`0x1007d120b..0x1007d123f`。初始 h=0，对每个有符号字符执行 `h = ((h + c) * 4 + (h >> 5)) & 65535`，遇 NUL 停止。不能排序宏或规整空格。
- 文件路径格式字符串：`0x100ba5ce8`，`Data/Shaders/%s/%.*s%d%s%s`。GLSL 对应 Bin 中的源名主体 + 十进制哈希 + 扩展名。

## 接入编辑器的行为

- LevelMesh 的 uniformName/valueType/vecValue/texValue 独立读取；LevelMaterial 的 name/type/vec/tex 独立读取。材质 ID 不再用于替代模型自身纹理参数。
- 模型预览采用自身 u_diffuse1Tex 与 u_diffuse1TexScale，修改后更新预览和原格式参数；不修改原始 shader。
- 全部四组 UV 保留；原 a_uv0 绑定 UV0+UV1，a_uv1 绑定 UV2+UV3，均为 vec4。位置、法线与顶点色也准备了原属性名称。
- 「材质与变体」列出配置的 136 个 shader，并可按模型和地形材质查看原始参数、图像声明、源码、绑定来源和 GUID 对应烘焙记录。
- 单个 shader 的编译检查保留；增加精确顶点/片元组合的 GPU 编译与链接诊断。当前设备没有可用 GPU 上下文时明确显示不可用。
- 空纹理、未声明参数、缺失文件及未逆向管线依赖均显示出来。空参数不能直接判为损坏：原游戏可能注入默认资源，仍需确认。

## 验证范围

332 个原始 GLSL 文件、136 对配置中的 shader 通过 glslang 离线编译和链接。对 WebGL2 仅移除核心导数的冗余 `GL_OES_standard_derivatives` 声明，着色器正文保持不变，检查同样通过。

33 张地图的 4442 个 LevelMesh/LevelMaterial 节点完成审计，其中 3935 个启用了自定义 shader，3930 个找到了配置变体；5 个 FogVolume 的 shader 声明来源待追踪。136 个节点引用缺失 PNG；缺失名称为 HeatTex、BasicGeoAtlas1、BasicGeoAtlas4、LifeForceMural02Sh、LifeForceMural。1117 个节点包含空纹理参数，原版默认资源待逆向。这些数量不能解释为原地图损坏。详情见 `shader-audit.json`。13 项测试覆盖原格式回写、字面量解析、已知变体、真实模型参数与未解决依赖。桌面测试使用临时复制的 WorldEmpty 和 Dawn，不改动原始游戏资产。

当前 Android PRoot 的 GPU 进程退出，离线检查不能证明 Windows 驱动兼容、GPU 上传或实际绘制。Windows 与原游戏加载验收仍待完成。

## 下一阶段的实现顺序

1. 从 Image 构造与 shader 参数应用函数确认空纹理的默认资源、gamma/mip 默认值及参数覆盖顺序；追踪审计中 FogVolume 的资源来源。
2. 逆向模型烘焙的子网格索引映射和 light0/1/2 属性格式，按 BST GUID 精确上传，验证顶点数与多 LOD 的对应关系。
3. 逆向 EnvNode 与 GlobalShaderUniforms 的太阳、天空、探针、点灯列表和阴影参数；按原 group 还原实际渲染状态。
4. 打通最小静态模型的原 GLSL 绘制、原 MRT 输出与后处理，再推进地形混合、裙边、云和原版烘焙。

地形碰撞/拓扑重建、体积云、一键烘焙及玩法类行为继续保留在完整清单中，尚未完成。
