# 模型与 BstBaked 烘焙查找／兼容规则

原 `0x1003f68d0` 已按完整函数恢复：资源引用和资源均存在、载入索引为非负 int32 时，依次扫描 48-byte 烘焙记录，返回第一个 GUID 相等的记录。函数不比较资源名；失败时不修改调用方的输出指针。重复 GUID 的原选择规则已核验，不能用后一个记录替换。

| 消费入口 | 原检查 | 已核验范围 |
| --- | --- | --- |
| BeamoBarn `0x100195050` | 记录 LOD 数量等于资源 LOD 数量 | `0x100195427..0x100195440` 原指令子段 |
| CloudCardBarn `0x10021fb40` | 首个展开烘焙 LOD 顶点数等于资源首个 LOD 渲染顶点数 | `0x10021fc86..0x10021fcb2` 原指令子段 |
| 模型网格绑定 `0x10045fa00` | 同一首个 LOD 顶点数检查，保留记录指针或清空 | `0x10045fb24..0x10045fb55` 原指令子段 |

36 组／11,710 次查询通过，包括全部 33 地图、10,653 条记录的 GUID 快照，空表、缺失 handle／resource、负载入索引、重复 GUID、不同资源名以及数量不一致。兼容检查执行原指令子段，在继续进入未恢复函数体之前使用返回跳板；这三项不代表消费函数整体运行通过。

输入表属于明确快照：展开数量来自已有 bake audit，失败展开明确写 0，资源载入状态明确指定。原载入函数会在缺失资源时将 GUID 改成 `0xffffffff`，采样数量不匹配时读取／跳过对应字节并清空已载入 LOD；原始文件记录不能直接充当最终运行表。现有编辑器按资源名／GUID 定位具体原始记录的接口继续保留，尚未将该快照核心接入完整模型加载。

Beamo 和 CloudCard 在查找前调用虚表 +0x30 获取对象 GUID；具体对象／运行创建类的分发、默认值和生命周期仍待闭合。61 条未关联记录继续保留，其中 44 条为 CharSkyRayMotherAnim，13 条为 DayEnd 云卡，另有 OrbitEndMegaBird 和 Storm 的三个模型。不能据名称或位置将它们擅自分配给当前对象。

实现：[baked-lookup.ts](../src/core/baked-lookup.ts)。原入口与调用链：[baked-bindings-native.json](baked-bindings-native.json)。原函数／子段报告：[baked-lookup-oracle.json](baked-lookup-oracle.json)。重建入口：`python3 tools/reverse-baked-bindings.py /path/to/Sky`，随后 `npx tsx tools/baked-lookup-oracle.ts`。

完整 LevelMesh／LevelMaterial／Beamo 生命周期、原资源注册与 GUID 来源、所有 LOD 展开、主视口原模型材质、裙边生成及 Visibility 遮挡链仍按联合清单继续恢复；本阶段不增加 Mesh.bin 的完整类运行检查项。
