# 模型材质原始参数接口

2026-11-20：继续优先建模类，恢复 LevelMesh shader 参数设置、按帧插值和向 Model 已就绪 LOD 的转发。完整 Model 创建、Scene 生命周期和 SetMeshShaderParam 类仍未完成。这里的接口可以与已有启用/变换接口共用同一个 LevelMesh 地址和实时 Model 指针。

## 原程序证据和独立执行

[入口、函数边界与代码哈希](model-parameter-native.json) 固定原执行文件 SHA256 `3fa493e2542638299fd54d64e1b62aeb5b81c8f290176d955c3e38a27fa72b20`。原程序字节在 QEMU 中执行；没有替换这些 LevelMesh/Model 函数，Vertex、资源管理、ResourceRef 和字符串池为显式 ABI 服务。

| 原入口 | 恢复范围 |
| --- | --- |
| LevelMesh find/allocate `0x100400c80` | 按 strcmp 名称查找；已有参数只校验类型，保留原 pass/index。最多 16 个参数；名称长度小于 28 字节。新参数递增计数后赋值，保留字符串别名/池增长和断言时已有写入。 |
| SetShaderParamFloat `0x1003ffe90` | 用原 float32 操作顺序计算当前过渡值，保存为起点，再写目标、清 elapsed、写 duration/dirty。 |
| SetShaderParamFloat4 `0x1003fff20` | 四分量完整计算后写起点，再读取目标向量；目标与起点别名时保留该顺序。 |
| SetShaderParamTex `0x1003fffc0` | 先查找/分配参数，再检查纹理名称长度。赋值支持原短/长字符串与自身赋值，清两项计时，置 dirty。 |
| LevelMesh update `0x100402060` | 正常、有效 uniform 路径；缓存 lookup index、原 MAXSS/MINSS 计时、float/vec4 插值、贴图解析/转发、dirty 合并。hot reload、无效 uniform 的日志流/交换移除和异常展开仍是明确边界。 |
| Model find `0x1004666a0` | 从指定 pass 的第一个 RenderData 查找原 uniform index，保留空表和初始化断言。 |
| Model float/vector/texture `0x100466710 / 0x1004669b0 / 0x100466e30` | 只向已就绪 MeshInstance LOD 转发，校验 RenderData 初始化，每次实际 Vertex 回调后重新读 LOD count。 |

[原程序对照](model-parameter-oracle.json) 为 **312 组输入 / 849 个快照 / 55,711,472 字节零差异**。覆盖途中重设目标、负/零 duration、计时夹取、NaN/无穷/负零、种子数值、短/长/嵌入 NUL 字符串、别名、类型/容量/长度断言和回调期间修改 count/dirty。算术核验为默认 MXCSR 舍入/非 flush-to-zero 模式，不宣称原硬件 NaN 或不同 MXCSR 模式完全一致。

## 原空纹理和 Scene 图像绑定

LevelMesh update `0x10040238c..0x100402396` 将空 C-string 选择为原图像 **Black**。编辑器仅在临时绑定中应用这个选择，Objects.level.bin 的原空名称不改写；非空名称仍使用原资源。

Scene `0x100059a50` 的 `0x10005a71e..0x10005a796` 明确查找/Observe 图像 **Caustics**，把纹理 GPU 指针绑定到 **u_caustics**，sampler 指针为 0。[完整 Scene 函数反汇编](../evidence/model-parameter-scene-globals.asm) 与字符串地址都进入证据报告。编辑器按此原资源身份加载实际图像及声明的 gamma/filter/mip 属性；完整 Scene 资源注册/引用生命周期、原 sampler 分配和 Metal 精度仍待恢复。

首个空纹理处理后的清点为 2,075 个材质依赖满足，DarkStone 进一步暴露 u_caustics；随后按原 Scene 证据接入该图像。最新 33 图 / 4,133 个 LevelMesh 中，**3,072** 个满足当前静态材质依赖，其中 **2,546** 个保存 render/enabled 允许初始显示；比上一轮分别增加 **1,104 / 1,035**。逐实例清点见 [model-draw-availability.json](model-draw-availability.json)。这些数目不能当完整类、可见性、原互动或游戏完成率。

## 同一模型实例的接口

`OriginalLevelMeshMaterialEndpoint` 提供 `setFloat/setVector/setTexture/update`，共用 LevelMesh 地址以及实时 `+0x228` Model 指针。参数表是原 `+0x1a0` 指针数组及 `+0x220` count，没有另创建一份冒充完整 Model 的对象。

`ModelParameterVertexServices` 由资源/渲染所有者提供 lookup、float、vector、texture。`LevelMeshParameterUpdateServices` 把原 LevelMesh 更新连接到原 Model 转发，纹理查找/引用/日志/析构由资源所有者承担。未来逻辑类可以操作这个 endpoint，与 TransformObject/Enable 操作同一实例。

Vulkan 的 `setModelParameterBinding` 是实际 GPU 绑定服务，按 object ID 更新同一模型绘制。绑定是瞬时覆盖，不修改保存对象；Scene 全局参数交给场景所有者，模型接口不会声称覆盖这些全局。数值修改只更新 uniform；纹理修改重新绑定，清理后恢复原对象材质。几何哈希包含 shader/参数名称类型/贴图及原顶点，排除矩阵和数值；同一模型的变换与参数修改不会每帧重复上传贴图。

## 实际渲染验证

[模型参数 GPU 检查](model-parameter-gpu-check.json) 使用原 DayHubCave #339 / PlatformRain_01 的网格、烘焙、shader、贴图和保存变换。参数/Model/单个已就绪 LOD 的内存为明确准备输入，未冒充完整原构造；原内核通过 Vertex 服务驱动真实 GPU。材质时间固定，场景光照/曝光沿现有声明的预览适配。

过渡到一半改变 **49,413** 个 HDR RGB 分量，途中重设目标改变 **50,021**，切换原 Black 改变 **63,287**。零 delta 不推进参数状态；清理后的 HDR 与初始帧字节完全相同。数值修改和同一实例重新导出保留材质上传次数，贴图切换及清理分别再上传一次。完整次数和实际图片哈希在报告中。
