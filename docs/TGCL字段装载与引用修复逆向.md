# TGCL 字段装载与引用修复逆向

本轮恢复 `Objects.level.bin` 的字段读取基础，将保存的字段字节写入已创建的对象，并收集待解析引用。已核验三个完整原函数和一个明确限定的原装载器区间，尚未实现完整 TGCL 装载、实际关卡启动或互动玩法。

| 原执行范围 | 实现 | 核验范围 |
| --- | --- | --- |
| `0x10040b1d0` ReadString 完整函数 | [字符串读取](../src/core/native-string-runtime.ts) | 原短/长字符串布局、赋值、游标及越界断言 |
| `0x1000198c0` 字符串扩容完整函数 | 同上 | 容量分支、前段/插入/尾段复制、先释放再写描述、uint64 长度错误；内存池仍为服务 |
| `0x10040b390` ReadFields 完整递归函数 | [字段读取](../src/core/tgcl-field-runtime.ts) | POD、字符串、延迟引用、数组与嵌套结构、已准备默认值缓存及失败后的内存状态 |
| `0x10040d2aa..0x10040d311` 装载器内引用修复区间 | 同上 | 对象表索引转指针，保留空引用、偏移修正和跳过空目标的顺序；不代表完整装载器 |

[原机器码报告](tgcl-field-oracle.json) 对照通过：417 组，81,985,536 字节内存，零差异。新增 36 组直接扩容用例覆盖容量边界、长度错误、别名以及前段/插入/尾段组合。其中 260 组采用真实关卡的保存字段字节与原注册成员偏移：184 个 Float、24 个 Clump、16 个 LevelMaterial、12 个 LevelMesh、12 个 Marker 和 12 个 Timeline。此报告的真实样本引用保留为待解析项；前向引用、循环引用与多对象修复使用独立合成用例核验。

原执行文件 SHA256：`3fa493e2542638299fd54d64e1b62aeb5b81c8f290176d955c3e38a27fa72b20`。C 核验器实际执行原机器码，反射转换、数组分配/构造及内存池分配/释放等边界由明确的服务提供。TypeScript 重放同一输入，比较完整测试内存、游标、引用数量、服务调用、长度错误和断言状态。

## 在关卡装载链中的位置

完整 TGCL 装载器先将序列化类/属性与原 metadata 匹配，准备成员访问及缺字段默认值缓存，再通过 ObjectFactory 和所属 Barn 创建实例。ReadFields 在这些准备结果上运行。全部节点存在后，装载器才把保存的对象索引转换为实际对象指针；后续注册、启动与更新另有阶段。

当前实现要求调用方提供准备完成的原上下文、真实对象存储和边界服务，不能直接作为独立游戏关卡加载器。静态解析器的字段编辑和这套原内存语义实现也分别验收。

| 上下文偏移 | 用途 |
| --- | --- |
| `+0x1420` | 序列化类表，每项 12 字节 |
| `+0x1428` | 每类缺字段默认值缓存范围，每项 8 字节 |
| `+0x1438` | 序列化属性表，每项 16 字节 |
| `+0x1440` | 已准备成员辅助信息，每项 32 字节 |
| `+0x1450` | 缺字段默认值缓存，每项 28 字节 |
| `+0x1470` | 保存字段数据起始地址 |
| `+0x1478` / `+0x147c` | 数据上限与当前游标，uint32 |
| `+0x1480` | 延迟引用表，每项 24 字节 |
| `+0x1488` / `+0x148c` | 引用表容量与已记录数量 |

## 原字段规则

属性类型 0 为 POD，1 为字符串，2 为对象引用，3 为数组。对象不存在或属性未匹配原成员时，仍消费保存数据；其中引用仍记录索引，但写入目标为 null。辅助信息包含成员偏移、指针调整值、MemVar 和反射 ArrayAllocator。

数组先读取元素数，已匹配成员即使长度为零也调用分配方法。随后按原 MemVar 取得数组地址，必要时解引用数组存储并断言非空。嵌套结构逐个要求有效对象槽、转换为 Object 后递归读字段；引用数组只记录待解析项。反射转换失败及空存储的原断言保留。

保存字段读取完成后，仅对非空对象应用已准备的 `Tool_DefaultValue` 缓存。POD 和指针默认值按原缓存字节复制，字符串默认值取常量对象中的字符串地址。没有对未保存字段自行清零，也没有由字段名猜默认值。

原字符串为 24 字节 libc++ 布局：短字符串容量为 22 字节，长字符串使用容量/长度/数据指针。赋值用 memmove 并写终止 NUL；ReadString 在赋值后再次读取源字符串长度，因此源与目标重叠时仍保持原游标结果。游标写入先于越界断言。

扩容函数 `0x1000198c0` 已恢复：先按 uint64 判断 `(0xfef - capacity) < delta` 并保留原回绕。容量不大于 `0x7e7` 时取请求量与二倍旧容量的较大值，小于 23 分配 23，否则按原 `(candidate + 16) & ~15` 计算；更大容量分配 `0xff0`。它依次复制前段、插入内容和尾段；旧容量不等于 22 时释放旧存储，随后才更新指针、分配量、长度和 NUL。长度错误单独记录，不伪装成 LevelObjects 断言。真实内存池内部仍未恢复。

引用修复在全部节点创建后进行：索引 `0xffffffff` 写 null，其余写 `objectTable[index] - adjustment`。空目标在读取其索引前就跳过；表基址与数量按原区间捕获。另见 [创建与事件槽连接](对象创建字段装载与事件槽连接逆向.md)：14 个真实 FloatMult 配置子图已在局部索引映射下连续创建/装载/修复/运算，完整关卡装载仍未完成。
