# 开发进展：模型烘焙映射与环境核心

目标仍为完整还原 Sky 0.3.18 的 Level。Windows 发布包维持 0.2.0；本文件记录之后的源码开发，不代表已重新发布或完成原版渲染。

## 烘焙照明

Mesh v28 的每个 LOD 原生结构长 184 bytes。`+0x34` 为绘制顶点数，`+0x40` 为烘焙采样数，`+0x98` 为逐绘制顶点的 u32 采样映射。读取入口 `0x100455e90`，LevelData 展开入口 `0x1003f4840`。统一照明重复采样 0，其他情况按映射复制每条 12-byte 记录。BstBaked 中照明之后的额外字节块不是该映射，保持原样。

例如 Cube 有 24 个顶点，映射从 `[2,1,0,5,4,3]` 开始。按顶点序号直接套用照明会产生错误。

源码现在保留全部资源 LOD，匹配模型名称与 GUID，验证采样数并展开 a_light0/1/2。新增按 LOD、采样编号编辑 12 bytes、绘制顶点定位采样、原始 RGB 通道查看；普通视口仍是编辑器预览。修改一条真实 Dawn 记录的测试确认只改变指定 12 个解压数据字节，额外块不变。桌面 IPC 检查覆盖定位、编辑、通道选择、撤销、重做和保存。

全量审计：1152 个资源、1231 个资源 LOD、33 张关卡、11311 个烘焙 LOD；11275 个成功映射，其中 551 个统一照明，36 个缺资源或对应 LOD，明确保留为未匹配。证据与结果见 `bake-evidence.json`、`bake-audit.json`。

照明解码依照原 Mesh49525.frag 的表达式：UNORM8、环境色分量平方除 alpha、天空混合、太阳可见度平方、方向和点光指数。未虚构环境默认值，也不把解码器称为烘焙器。

## 环境运行逻辑

使用 Mach-O 的 LC_FUNCTION_STARTS 识别 54121 个真实函数边界；反汇编明确排除内嵌跳转表，避免将数据当作指令。

- `0x10031a230`：12 类字段插值。标量采用 `(1-t)*a+t*b`，向量采用 `a+(b-a)*t`；Vector3 保留第 4 存储分量，Color 限制插值权重，bool 在 0.5 切换。每个 float32 运算按原指令舍入。
- `0x10031a6f0`：直接 EnvNode 空间权重。旋转 OBB、全尺寸 scale、最近点、外部 falloff、容差和时间 alpha 相乘；Clump 分支的对象解析仍待接入。
- `0x10031a450`：直接 EnvNode 淡入淡出。激活时计时重置为 duration+fadeIn，到期先关闭节点，再淡出；分别保留当前 alpha、剩余时间和上次 enabled 状态。
- `0x10031aec0`：四层按顺序合成，层内增量计算加权平均，再以 `min(1, 总权重)` 与累积环境插值。八组参数的 40 个元类型字段映射已恢复；准确的 Level 创建与事件顺序仍待完整还原。

验证使用静态 x64 测试程序映射原可执行文件，在 QEMU 中直接调用未改动的原机器码，无游戏初始化、不写游戏文件。396 个字段插值、378 个空间权重、576 个计时与淡入淡出样本逐字节一致。该证据证明上述函数分支，不证明整个游戏环境或 GPU 渲染一致。可运行 `tools/reverse-environment.py 原程序 --oracle` 重建，依赖 capstone、qemu-user 和 x86_64-linux-gnu-gcc。

## 全局 uniform

`0x100059a50` 注册了 29 个 Ambience 全局 uniform，其中 25 个已关联具体字段地址，例如 u_sunDir→Ambience+0x290、u_sunColor→+0x20、u_pointLight→+0x2a0。天空、探针、雾、灯塔等来源列在 `environment-evidence.json`，并显示于材质检查界面。另 4 个纹理资源的对象来源需要继续追踪。

`0x100793f30` 的注册表最多 128 项，每项 56 bytes，名字容量 28 bytes，保留数据指针及组件元数据；同名注册替换原槽位。原版会随运行状态更新指针所指数据，不能用节点属性直接替代所有 uniform。

## 公开属性到内部环境结构

继续恢复了 EnvNode `0x10031bb10`、SetEnvDefault `0x10031be30`、SetEnvHull `0x10031c050` 的转换。原版会将公开属性复制到内嵌 EnvVars，并把雾密度乘以原 float32 常量 0.01，计算雾距离倒数，清除体积雾强度符号位、按原阈值设置启用与正向标志。转换表由原指令提取，18 个完整存储样本与未修改原机器码逐字节一致，包括未写入字节和正负零。

随后从完整 TGCL 加载器确认缺属性读取 Tool_DefaultValue，恢复三类环境对象的 122 条默认规则。原向量默认解析路径核对了 8 个唯一输入；三分量 Color 的第 4 分量为 0。该样本中的 macOS libc 导入绑定 Linux libc，验证边界列于 `environment-default-oracle.json`。这些默认值只补全运行输入，原序列化字段优先，原文件没有改动。

`environment-audit.json` 覆盖 33 张地图的 167 个环境对象，使用原默认值补齐 478 个缺字段，解决原先 21 个对象缺雾距离的问题；1336 个参数组、6680 个混合字段全部完整。对象抽屉可查看八组换算结果，编辑公开字段后重新计算。桌面 IPC 已验证临时 Dawn 副本中的 fogDensity 实时换算和原格式保存。

环境注册、时间缩放与夹取、共享 enabled 及完整四层更新/混合链，另有 96 个场景的 960 帧、876 条注册记录与原机器码逐字节一致。此检查使用明确初始输出与单字段测试元数据，不能替代完整 Level 初始化。当时源码通过 29 项测试、类型检查与构建。

## Clump 环境范围与真实地图引用

恢复了 `0x10031b3c0` 的 Marker Clump 注册路径。范围必须非空；每项 Object 引用通过原类型转换还原到 Marker，Object 子对象位于 Marker+8。空间函数 `0x10031a6f0` 对所有直接 Marker 的旋转盒体取最大权重，再乘一次时间 alpha；不会递归展开嵌套 Clump，也不会按各 Marker 的 enabled 过滤盒体。

注册和 `0x10031a450` 的计时只读取第一个 Marker 的 enabled。到期会写回第一个 Marker 的启用字节；八组参数与引用相同 Marker 的多个范围共享这份状态。源码为 Marker ID 建立共享对象，避免从序列化引用重建后把启用状态拆成多份。空范围、缺失引用和未支持的类在检查中保留为不完整，不能开始运行；未确认的派生 Marker 类转换仍未支持。

新的 QEMU 对照保留未修改的原空间、计时、注册和完整更新/混合函数，也保留 Object/Marker 元类虚表、Object→Marker 偏移转换、原类查询及 enabled 读取。只对测试参数组提供单字段元数据、明确初始化输入，并将原导入 bzero 绑定 memset。720 个空间样本、384 个计时样本及 192 个场景的 1920 帧逐字节一致，覆盖 1/3/8 个 Marker、四层位置、浮点/Vector3/Color/bool 参数与多组共享到期行为。此证据不代表完整游戏初始化或事件分发已还原。

33 张地图的范围审计：134 个直接 EnvNode 范围与 4 个 SetEnvHull 范围全部输入完整。Storm 的三个控制 Marker 为 #206/#997/#680，原启用状态分别 true/false/true；StormEnd 为 #897，原状态 false。检查界面可跳转到控制 Marker、查看盒体成员，并查询当前编辑器相机位置的空间权重；该查询明确不含时间权重，也不是完整环境合成或原 shader 绘制。原文件保持不变。

另外确认 `0x100319d40` 的创建队列最多 16 个 EnvNode、每个槽长 1040 bytes；Level 加载按队列索引递增注册。TGCL→ObjectFactory 创建顺序已确认，完整自动事件与初始全局输出仍待核实。详见 `environment-clumps.json`、`environment-clump-oracle.json` 和 `environment-audit.json`。发布包未重打包。

## ModuleBarn 初始化与 EnvNode 创建队列

Game `0x100376f80` 通过 ModuleBarn 安装 Initialize 回调，并以 groupMask=1、reverse=false 调用 `0x1007b1b40`。安装函数 `0x1007b17c0` 修改已有槽位，不改变调度顺序。ModuleBarn `0x1007b0620` 使用 `0x1007b02c0` 按容器字段存储地址升序排序，再构建函数表。Game.environment 位于 +680，cloudBarn 位于 +952，前者先初始化。

环境全局注册顺序是太阳、天空、雾、泛光、曝光、点光、体积雾、云。EnvNode 内部注册顺序则是太阳、天空、雾、泛光、曝光、点光、云、体积雾。两种顺序分别保存在 `environment-load.json`，运行适配器按全局顺序处理共享 enabled 与各组独立计时，检查界面按该顺序展示参数。

Environment 构造函数 `0x10031c720` 在创建地图之前调用 `0x10031c830` 构造全部 16 个队列槽位。CreateEnvNode 仅返回下一个槽位。TGCL 加载器 `0x10040bc00` 按文件节点顺序调用 ObjectFactory，再读取字段及补充缺字段默认值；OnLevelLoad `0x1003198d0` 清空八组默认指针和四层范围计数，关闭注册，再按队列顺序转换/注册节点。此步骤保留输出和队列数量。完整自动事件顺序和初始 Ambience 输出尚未还原。

新增 `createQueuedEnvironmentRuntime` 接入真实 TGCL 节点、原始变换、全部 40 个混合字段、计时与创建顺序；必须显式提供已初始化的全局输出。其范围是 Environment.OnLevelLoad 的队列注册阶段，SetEnvDefault/SetEnvHull 自动事件仍单独列为待接入，不在此阶段按文件位置擅自执行。33 张地图的创建队列输入完整，最大队列 13 个节点。

`reverse-environment-load.py --oracle` 执行未改动的原 ModuleBarn 排序、回调安装与向前调度，以及 Environment 构造、队列取用、加载重置、EnvNode 转换/注册和完整更新/合成指令。134 个真实地图节点、全部八组 40 个字段、396 帧与 TypeScript 逐字节一致。测试显式提供类元数据、全部字段缓存、初始输出及零向量全局；保留原 getter/注册/更新代码，libc 导入绑定 Linux libc。没有执行原 TGCL 解析器、ObjectFactory、初次字段缓存构建或完整游戏启动。证据见 `environment-load-oracle.json` 与 `tests/fixtures/env-load-native.json`。

当前源码通过 32 项测试。桌面检查新增真实 Dawn 的队列位置、16 槽上限，以及体积雾先于云的顺序；Windows 发布包维持 0.2.0。
