# 画面清晰度与裙边修复

0.3.7，2026-11-22。用户确认 0.3.6 明显流畅了，但画面模糊、有像素感；进一步要求流畅、均衡、清晰三档都达到 60–70 FPS 以上。当前没有该显卡的新分段耗时或 0.3.7 实测，不能宣称帧率目标已经达到。

## 三档清晰度

右下角下拉框现在有三个可切换档位，选择保存在本机。所有档位继续完整效果路径，保留已接入的原材质、纹理、云雾、运动向量、TemporalAa 和 Tonemap。

| 档位 | 分辨率行为 |
| --- | --- |
| 流畅 | 保留 0.3.6 动态分辨率，GT 1030 长边范围 384–1600 |
| 均衡 | Windows 默认，从原生分辨率开始，线性尺寸在原生的 67%–100% 之间调节 |
| 清晰 | 按视口实际像素（含设备像素比）渲染；不因慢帧下降分辨率 |

均衡的 67% 指宽、高的线性比例，相当于约 45% 的原生像素量。清晰档会增加渲染工作量，实际帧率可能下降。协议长边上限是 4096；超过上限保持宽高比缩放。现有应用设备像素比上限仍为桌面 2、Android 4。

HUD 增加渲染比例和档位，尺寸取上一张已经显示的完整图像，避免把尚未完成的目标尺寸当作已显示尺寸。切换时保留上一帧，收到完整图像后才替换 Canvas 尺寸和像素。没有新增锐化或更改原抗锯齿 shader。

完整视图静止或暂停后，补齐原时间抗锯齿的八相采样，再停止按需渲染。之前只补少量云历史帧，会让静止边缘的时间采样不足。动画时仍使用原有连续帧调度，每次最多一个请求。

## 裙边输入格式

原 SkirtBarn Initialize `0x1005abf50` 对 slot 3 设置原格式 24、属性 25，使用加载顶点的末尾四字节。这与 slot 0 法线的原 SNORM4 格式一致；原机器码调用参数已捕获在 `skirt-barn-native.json` 与 `skirt-barn-native.json.gz` fixture 中。原格式 28 则用于无符号材质和照明。

之前编辑器把 `a_userData1` 当成 UNORM4。现在 Three 属性按 Int8Array 归一化读取，Vulkan 描述按 `R8G8B8A8_SNORM` 读取；原字节不变。正数应除以 127，负数保留符号，-128 映射到 -1。RGB 参与原沙地裙边纹理方向权重，W 参与岩石、草、沙和云裙边的透明计算；旧格式会改变方向和透明过渡。

裙边材质扫描也恢复原规则：四个非零 ID 都检查，未知 ID 没有材质位，忽略该 ID；不因未知 ID 使整张地图加载失败。已知 ID 即使权重为零仍保留批次，与原函数捕获一致。

## 验证与边界

验收记录在 `viewport-display-verification.json`、`skirt-render-check.json` 和 `viewport-display-smoke.json`。

裙边检查覆盖 33 张地图的全部 2,533 条裙边、363,788 个顶点，逐分量检查有符号读取和原始字节不变。真实 Vulkan fetch 对所有 256 个字节值的四个分量对照独立 SNORM 计算；材质表实际使用的岩石/雨天岩石、沙/雨天沙、草和云共六种裙边 shader 在明确受控输入下核验透明输出，原 shader 源码未改写。原生函数 fixture 的材质掩码单独用于回归。

实际 Electron 检查三档切换、已显示图像保留、像素不全白且完全不透明、完整阶段与裙边 shader、DPI 和选择记忆。环境是 ARM64 软件 Vulkan，不能用于 GT 1030 的 FPS 验收。

0.3.6 的原生云滤波、最终 RGBA 打包、曝光样本批量采集、缓存和单请求调度保留。三档都达到 60–70 FPS 以上仍需 Windows 真机分段测量与进一步优化。没有把降低分辨率、设置帧预算或本机软件 Vulkan 数字算作高帧率达标，也没有把这次格式修复算作裙边全部问题或原游戏完整画面已闭合。
