冥龙的柔软身体来自原版 `FloppySpine` 更新，当前基础预览此前没有调用它，只采样内嵌动画，再移动和旋转整个模型。

已直接核对所提供 Sky 0.3.18 可执行文件，SHA256 为 `3fa493e2542638299fd54d64e1b62aeb5b81c8f290176d955c3e38a27fa72b20`。原函数中的断言字符串明确包含 `FloppySpine.cpp` 和 `not enough _Sim joints to simulate`。

原版处理流程：

1. 冥龙创建 Model 时开启柔性脊柱选项。Model 构造在 `0x100469188..0x1004691e5` 创建 FloppySpine。
2. FloppySpine 按 `_Sim` 骨骼找出末端，再沿父节点组织骨节。真实冥龙共有九节：`M_neckLow_Sim`、`M_belly_Sim` 和 `M_tail1_Sim` 至 `M_tail7_Sim`。翅膀是这些骨骼的子分支，会随脊柱弯曲，同时保留动画里的拍动。
3. 保留前端位置的 128 项空间历史。前端移动超过与脊柱总长度有关的采样距离时插入位置；后续骨节沿历史路径按各节长度选择目标。
4. 每次更新使用 `旧骨节位置 × 0.7 + 历史目标 × 0.3`，执行十轮长度约束，并再从前往后投影一次，保持求解链的节间距离。
5. 逐节调整朝向，让父骨骼朝向下一骨节的求解位置，保留动画本身的平移变化，然后重新计算骨骼矩阵并蒙皮。因此转弯不是整条身体一起转，尾部会逐节跟随。
6. 头部另有平滑控制。`0x100272160` 回调只将 `DarkCreature +0x110` 中的世界四元数写入 `M_head_Con`；这与 FloppySpine 是两个不同步骤。

Model 的实际顺序在 `0x10046a8b6..0x10046a95e`：主动画、次动画、叠加动画、刷新矩阵、头部回调、刷新矩阵、柔性脊柱、再次刷新矩阵。不能把普通动画采样或通用人体动态权重当作冥龙的柔性脊柱。

本次代码已把原空间求解算法和已有原头部平滑内核接入冥龙预览，修正前进方向为模型的负 Z。缩放来自原 Load 的 `1.5` 乘原 Update 的 `0.125`，即保存矩阵缩放的 `0.1875`；不凭模型包围盒猜体型。暂停保留当前骨骼状态，停止和切图清理历史并恢复原几何。

源码启动也读取 `dist/vulkan-shaders` 中已生成的预编译缓存，发布包继续读取 `resources/vulkan-shaders`。这避免源码启动绕过已有缓存，在没有 glslangValidator 的机器上重复尝试编译。

核验：`tools/floppy-spine-oracle.ts` 在 QEMU x64 下调用未改写的原 FloppySpine.Update，已初始化骨节的 24 组轨迹、1,152 帧、4,796,352 比较字节无差异，包括弯曲路径和突然位移。比较覆盖骨节 XYZ 与保留的历史流。变换/分配/复制为显式服务，其中重叠历史复制使用 memmove。独立回归进一步检查真实冥龙骨节朝向与蒙皮顶点、暂停、重播、还原。

边界：这是原版柔性脊柱的空间求解和编辑器接线，尚不是完整原版生物验收。编辑器仍提供简化巡逻/接近轨迹；骨骼发现和初始历史由真实资源适配，瞄准使用 Three.js 的矩阵/四元数，头部 libm 使用 JS Math。完整 Model 动画分层、原巡逻/追击 AI、外观材质和颜色、眼球/投影/音效等仍需分别接入，Windows 真机表现尚未验证。
